# 支払管理（SEIQ）

## 実装範囲

- `/expenses`：対象月別コスト、支払日別実績、全期間の未払い・期限超過、今日から7日以内、費目・支払先検索、月別／費目別グラフ、20件単位の一覧。
- `/expenses/new`、`/expenses/[expenseId]/edit`：登録・編集・全額支払いの記録／解除。
- PDF添付1件・3MiBまで。DBの別テーブルに保管。認証済みの所有者だけが添付としてダウンロードでき、共有リンクは作らない。
- 既存のユーザー、請求書、会社は変更せず、ExpenseとExpenseAttachmentの2テーブルを追加する。
- 金額は税込の実支払額。対象月と実際の支払日は別項目。請求額との差額を利益・残高とは表示しない。
- 銀行振込、自動支払い、定期支払い自動生成、一部払い、承認フロー、入金消込は対象外。

## 本番反映前

1. 本番DBのバックアップを取得し、復元手順を確認する（この開発作業では本番バックアップ・DB変更はしていない）。
2. 対象のDB接続先を確認して `prisma migrate deploy` を実行する。追加SQLは `prisma/migrations/20260917090000_expense_management/migration.sql`。
3. マイグレーション成功後にアプリをデプロイする。ダッシュボードもExpenseを参照するため、DB適用前に新版へ切り替えない。
4. 新しい支払データ／PDFをバックアップ対象に含める。既存ユーザーで請求書・取引先が維持されていることを確認する。
5. アプリをロールバックする場合、追加テーブルを削除しない。旧版は追加テーブルを使わない。

## 検証

`npm test` はDBを使わないテストを実行する。`tests/expense-db.test.ts` は通常スキップする。
使い捨てのPostgreSQLにだけ全マイグレーションを適用し、`RUN_EXPENSE_DB_TESTS=1` とそのDBの `DATABASE_URL` を指定すると、実DBへの登録・添付・二重登録防止・所有者分離・支払記録・添付解除・古いバージョンの更新拒否を検証する。本番DBでは実行しない。
