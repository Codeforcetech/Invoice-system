# フェーズ8 計画: 申告・法対応（実装前の計画。コード変更なし）

作成日 2026-10-03。決定事項: 税率は 10%・8%（軽減）・非課税・免税、証憑はDB保存のまま、登録番号は形式チェックのみ。

## 現状（調査結果）

- 請求書の税率は請求書ごとに1つ（`Invoice.taxRate`、基点 bps）。明細（`InvoiceItem`）に税率・税区分がない。税額は小計全体に1回だけ計算（`lib/invoice/calculateInvoice.ts`）。
- インボイス登録番号は `SystemSetting.invoiceRegistrationNumber`（自由入力・最大2000文字・形式チェックなし）。請求書の画面（`invoice-print-view.tsx`）とPDF（`lib/pdf/render-invoice.tsx`）に「登録番号: …」を表示。
- 仕訳明細（`JournalLine`）に税区分がない。会計は税込経理（フェーズ1の方針）。消費税の区分別集計はできない。
- 証憑は経費の添付PDF1件（`ExpenseAttachment`）と経費精算の領収書1件（`ClaimReceipt`）。いずれもDB（BYTEA）保存。日付・金額・取引先での検索、訂正・削除の履歴はない。

## 守ること

- 既存の発行済み請求書の金額は変更しない。再計算もしない。
- 既存の請求書作成フロー（取引先→件名→明細→プレビュー→発行）と画面の見た目は維持する。
- 追加のみのマイグレーション。適用前にローカルDBを保存する。
- 「適格請求書・電子帳簿保存法に適合」とは表現しない。要件への対応状況を示し、最終確認は利用者・税理士が行う、と画面とドキュメントに明記する。

## ステップ

### 8-1 登録番号と税区分の土台

- 登録番号を「T＋13桁の数字」で検証（設定画面・保存時の両方）。空欄は許可（免税事業者）。既存の値は消さず、不正形式の既存値は警告表示のみ。
- 税区分マスタ（コード定数）: 課税10%、課税8%（軽減）、非課税、免税、不課税。税率は bps で保持。
- `InvoiceItem.taxCategory`（nullable。null＝請求書の税率を引き継ぐ＝従来動作）を追加。既存行は変更しない。

### 8-2 適格請求書の計算と表示

- 計算: 税率ごとに明細を集計し、**税率ごとに1回**端数処理して税額を出す（インボイス制度の要件）。合計は各税率の合計の和。明細がすべて同一税率なら従来と同じ金額になることをテストで固定。
- 請求書フォームの明細行に税区分の選択を追加（既定は請求書の税率）。軽減税率の明細には「※」を付ける。
- 画面・PDF・共有ページの請求書に、税率ごとの対価合計と税額、登録番号、軽減税率対象の凡例を表示。
- 発行済みの請求書は従来の合計を維持。明細に税区分がない請求書は従来の表示のまま。
- 源泉徴収の計算との関係（小計基準）を壊さない。

### 8-3 会計側の税区分

- `JournalLine.taxCategory`（nullable）を追加。請求書・支払・経費精算からの自動仕訳で、売上は明細の税区分、費用は入力された税区分を保持。手入力仕訳は任意入力。
- 「消費税の区分別集計」レポート（期間内の課税売上・課税仕入・非課税などを税率別に集計。CSV/PDF出力）。税込経理の金額から税額を内訳計算する。**納付税額の計算・申告書の作成は含まない。**
- 既存の仕訳は税区分なし（未設定）のまま。レポートでは「未設定」として別枠に出し、推測で割り当てない。

### 8-4 電子帳簿保存法のファイルボックス

- 新テーブル `EvidenceFile`: 事業所、取引日、金額、取引先、種類（領収書・請求書・契約書・その他）、ファイル名、MIME、データ、SHA-256、登録者、登録日時、メモ。検索3項目（取引日・金額・取引先）を必須入力にして、範囲検索・複合検索ができる。
- 訂正・削除は履歴テーブルに残し、元ファイルは削除せず「無効」にする方式。登録・訂正・無効化は操作ログ（フェーズ7）にも記録。権限は入力可で登録、承認可で無効化、管理者で保存期間設定の確認。
- 既存の経費添付・経費精算の領収書は、元の保存先を変えずに、ファイルボックスから参照できるようにする（コピー登録は利用者の操作）。
- アップロード検証（形式・サイズ・実体確認）は経費精算の既存実装を再利用。
- 保存期間（原則7年、欠損金の繰越がある場合は10年）を画面で案内。期間内の物理削除は不可。

### 8-5 確定申告書類のたたき台（将来）

- 今回は実装しない。8-3の集計と損益レポートを元に、質問形式の入力から出力する設計を、8-1〜8-4の運用後に相談する。

## テスト方針

- 税額計算: 単一税率の既存金額が変わらないこと、混在時に税率ごとに1回の端数処理になること、源泉徴収との整合、0円・端数・大きな金額。
- マイグレーション: 既存請求書の合計・PDFの表示が適用前後で変わらないこと。
- 登録番号: 正常・桁違い・全角・小文字・空欄。
- ファイルボックス: 検索条件、無効化後も元データが残ること、所有者・権限の分離、ハッシュの一致、操作ログ。
- 画面: 請求書作成フローの通しと、PC・スマホ幅の表示確認。

## 想定する規模と順序

8-1 → 8-2 → 8-3 → 8-4 の順に、各ステップでテストと画面確認を行い、ステップごとにコミットする。8-2 が最も影響が大きい（請求書の計算・画面・PDF）。

## 未決・要確認

- 簡易課税・2割特例は今回の対象外（決定済み）。
- 外部ストレージへの移行は、証憑の件数と容量が増えた時点で別途検討。
- 登録番号の国税庁照合は今回の対象外（決定済み）。
- 適格請求書の記載事項（受領者名の扱い、返還インボイス・修正インボイス）は、実装前に税理士の確認を推奨。
