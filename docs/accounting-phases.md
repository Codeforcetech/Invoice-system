# 会計拡張の実装・検証記録

## 範囲と互換性

既存の色・レイアウト・ボタン・カードを流用し、既存メニューの順番を維持して「会計・帳簿」の入口だけ追加する。請求書作成フローは維持する。フェーズ1を確認してからフェーズ2へ進む。フェーズ7（権限管理・内部統制）の第1段階まで実装。フェーズ8は別途合意する。

この段階は円・税込経理。仕訳は従来のユーザー所有単位に分離する（複数ユーザーで同一事業所を共有する権限モデルはフェーズ7で移行設計が必要）。税務申告・電子帳簿保存法への適合を宣言するものではない。

税込経理の参照: https://www.nta.go.jp/taxes/shiraberu/taxanswer/shohi/6375.htm

## フェーズ1

- 初期設定で会計開始日・業種（サービス/小売/建設）を選択。開始残高は手動伝票で登録。
- 勘定科目の追加・名称変更・無効化。標準科目は自動仕訳用にコード・分類・有効状態を固定。使用済み科目のコード・分類も固定。
- 振替伝票（複合仕訳）と固定科目の帳簿形式入力。
- 借貸一致、正の整数円、所有者をアプリとDBの両方で検証。送信キーでリトライの二重計上防止。
- 訂正は取消仕訳を残す方式。元帳には繰越と取消を含む残高を表示。
- CSVはUTF-8 BOM付き、数式インジェクションをエスケープ。PDFは日本語フォントを同梱し、認証・所有者確認後に生成。1回5,000伝票まで、PDFは1,000行まで。超過時は期間を狭める案内。

## 本番への移行

本番反映は別作業。DBバックアップと復元試験後に、追加テーブル・nullable列のマイグレーションを先行適用する。既存請求書と取引先を削除するSQLは含めない。移行時に既存請求書を自動で仕訳化しない。ロールバック時は追加テーブルを残し、会計データを削除しない。

## フェーズ2

- 発行済み請求書: 売掛金 / 売上高を税込総額で計上。入金: 普通預金 + 仮払税金（源泉徴収）/ 売掛金。源泉徴収を売上減額として扱わない。
- 支払管理: 対象月1日に費用 / 買掛金（仕入）または未払金（その他）、実際の支払日に買掛金・未払金 / 普通預金。費用の精密な日付管理・支払口座別管理は今後の拡張。
- 同一トランザクション内で元データと仕訳を保存し、片側だけの成功を防止。所有者単位のトランザクションロックと元レコードの更新日時で並行操作を保護。
- 連携内容をハッシュ比較し、同じ内容の再保存は仕訳を増やさない。変更時は旧仕訳の逆仕訳と新仕訳を同日に記録して履歴を残す。
- 既存データは開始日以降の対象を確認して取り込む。開始日より前の発行分は自動連携対象外。開始残高を手動で移す場合は二重計上を避けること。
- 入金消込: 手動の銀行明細入力と同一取引先の発行済み請求書を全額照合。金額・バージョン・未入金を確認し、複数請求を原子的に消込。履歴から全件まとめて取消可能。一部入金・振込手数料差引は未対応。銀行CSVはフェーズ3で追加。
- 定期請求: 登録時の明細・税率を保持する毎月のテンプレート。対象月の「下書きを生成」で作成。31日がない月は月末。同じルール・月のリトライは同じ下書きを返す。自動実行スケジューラ・自動発行・メール送信は行わない。
- 合算請求: 同一取引先・税率・源泉徴収設定の未発行下書きを合算。元の下書きは残して合算先へ誘導し、通常一覧・件数から除外。元の下書きからの再発行をサーバーで禁止。合算後は税額を再計算するため端数差があり、発行前の確認が必要。発行済み請求の再合算はしない。

## フェーズ3: CSV明細・仕訳提案・自動登録ルール

- 「会計・帳簿」→「明細取込・自動仕訳」。既存サイドバー・カラー・部品を維持。
- 銀行口座（資産科目）とカード（負債科目）を登録。銀行APIへの接続・認証情報の保存は行わない。
- UTF-8 / Shift_JISのCSVに対応。日付・摘要・入出金別 / 符号付き金額 / カード利用額・任意の明細IDを列指定。引用符・改行・カンマを解析し、プレビュー後に取り込む。先頭は見出し、1MB・500件・50列まで、西暦年月日と整数円。先頭の説明行や合計行は除外が必要。
- 銀行は入金＋ / 出金−、カードは利用額＋ / 返金−。会計開始日前・未来日・小数円・不正金額・文字化け等があれば全体を拒否。元ファイルは保存せず、正規化した明細とファイル名を保存。
- 明細IDがあれば口座単位のIDで重複排除。同じIDの内容が変わっていたら拒否。IDがない場合は日付・正規化摘要・金額・同一行の出現順で判定。取込後にID有無の方式を切り替えることは禁止。
- IDなしの同日・同額・同じ摘要の取引を別ファイルに分けると識別できないため、同日の明細はまとめて取り込む。口座名を変えて別口座として登録すると別の重複判定領域になるため、継続利用する口座は既存の登録先を使う。
- 過去の手入力仕訳（直近1,000件・取消を除く）の摘要・入出金一致で一意の相手科目があれば提案。承認時の学習は「口座・正規化摘要の完全一致・入出金」のルールとして保存。曖昧な候補は選択しない。金額はCSV値を使用。
- 学習直後は提案のみ。自動登録を有効化したルールと、取込時の自動登録チェックの両方がある場合に同じトランザクション内で仕訳も登録。ルールは停止・再開可能。後から自動化を有効にしても取込済み未処理行には遡及しない。
- 未処理 / 登録済み / 既存仕訳と照合済み / 対象外を一覧化、200件ずつページ切替。各仕訳へ日付で帳簿を開ける。
- すでに請求・支払管理で記帳した明細は、仕訳IDを使い同日・同じ口座科目・同額の有効な既存仕訳と照合（追加仕訳なし）。照合先を後から取り消した場合は要再確認を表示。請求書への自動マッチング・一部入金・差額調整は未対応。
- 登録取消は逆仕訳を残し、未処理へ戻す。対応ルールの自動登録も解除。既存仕訳との照合解除は元仕訳を変えない。取消済みでも明細を消さず、再取込による重複を防ぐ。
- 所有者検証、口座ごとの重複一意制約、口座/科目/仕訳の所有者複合外部キー、トランザクションロック、更新日時による古い操作の拒否を実装。
- マイグレーション `20260927110000_statement_import` はテーブルと制約の追加のみ。検証DBに適用済み。本番は未適用。
- OCR、銀行API、AI推論、承認者ワークフローはこのフェーズに含まない。

## フェーズ4: 経費精算と承認・通知

- 「経費精算」「お知らせ」を既存ナビゲーションに追加。カード・入力欄・色・既存請求フローは維持。
- 精算先は既存会計所有者に紐付ける追加テーブル。既存ユーザー・取引先・請求書の所有権は移行しない。会計初期設定済みの利用者が自分の精算先を作り、登録済みメールアドレスでメンバーを設定。
- 申請のみ／申請・承認の専用権限。管理者と有効な承認者は提出済み申請のみ閲覧可能。他人の下書きは非公開。本人の過去申請は利用停止後も閲覧可能だが、操作は停止。グローバルADMINでも他の精算先を自動閲覧できない。自分の申請は承認不可。
- 下書き保存→申請→承認／理由付き差戻し→再申請。申請時に添付を必須化。承認待ちは編集不可だが本人が取下げ可能。
- 3MB以内のPDF・JPEG・PNG・WebP。画像を実デコードし、ピクセル上限と形式を検証、向き補正・最大2000px・WebP化してメタデータを除去。PDFはヘッダ/終端を確認し、権限確認付きダウンロードのみ。ウイルススキャン/法対応原本保管を実装済みと表現しない。
- 承認者が費用科目を確認。承認日ではなく経費日で費用／未払金を同一トランザクション内に記帳。実際の支払い後は管理者が精算日・支払口座を指定し、未払金／支払口座を記帳。送金機能ではない。
- 承認取消・精算取消は理由必須で元の日付の逆仕訳を残す。精算済みの承認取消は先に精算取消が必要。再申請の版番号と各操作の実行者・日時・コメントを保存。
- 会計所有者ロック＋更新日時で同時操作を制御。仕訳失敗時は状態変更・通知を含めロールバック。所有者を含む複合外部キーで仕訳との整合性を保護。

- アプリ内通知は申請先の承認者へ承認依頼、申請者へ承認・差戻し・精算・取消結果を記録。未読件数、既読操作、本人の通知だけの一覧を用意。
- メールは本人のオプトインとResend設定が必要。添付・金額を含めず、ログイン必須の画面リンクのみ。設定がなければ送信せず、アプリ内で未設定と案内。通知と送信待ち状態は処理のトランザクションで永続化。

## フェーズ5: 固定資産台帳・減価償却（2026-09-28）

- 「会計・帳簿」内の「固定資産」から開く。サイドバーの順序・配色・共通部品を維持。台帳は名称検索・管理中/保管済み・50件単位のページ切替。資産名、取得日、使用開始日、税込取得価額、耐用年数、償却方法、年度開始月、科目、メモを保存。
- 入力しながら初年度の見込み金額を表示。保存後は年度別の月次償却予定と記帳済みの帳簿価額を分けて表示する。使い方ガイドに手順を追加。
- 定額法、200％定率法、非償却。耐用年数2〜50年の事業専用有形固定資産、残存簿価1円、12か月の事業年度、直接法に対応。定額法は2007-04-01以降、200％定率法は2012-04-01以降の取得資産。定率法は保証額との比較・改定取得価額の固定を実装。年度開始月を1〜12月から指定。
- 償却率は国税庁の表を整数で保持。月途中の使用開始も1か月として計算し、年度内の累計額を円未満切捨てして月額に配分。月次合計と年次合計が一致する。会計管理用の計算で、申告書の税務調整・税額計算は行わない。
- 参照: [国税庁・償却率等表（5ページ）](https://www.nta.go.jp/taxes/shiraberu/shinkoku/tebiki/2025/pdf/034.pdf)、[償却限度額の計算方法](https://www.nta.go.jp/taxes/shiraberu/taxanswer/hojin/5410.htm)。
- 月次または年度の未登録分を確認してボタンで仕訳を自動生成。月末・年度末以前の記帳を拒否。取得時の仕訳は別途必要で、資産登録では購入・支払い仕訳を作らない。スケジューラによる無操作の定期起票は未実装。
- 年度まとめて登録は未登録月だけを集計し、年度末に1仕訳を登録。月次・年次とも資産×対象月の有効レコード一意制約を共有。古い期間の未登録があると先の期間を登録できない。定額法/定率法とも借方「償却費の科目」・貸方「資産科目」で帳簿に反映。
- 利用者単位のトランザクションロック、更新日時照合、版番号付き仕訳キー、借貸一致検証、所有者を含む複合外部キーで保護。失敗時は記帳と台帳更新を全てロールバック。
- 取消は最新期間から理由付きで実行し、元の日付の逆仕訳と取消履歴を保存。年次の取消は同じ仕訳の全対象月を戻す。再登録可能。履歴のある資産は名称・メモのみ編集可。紐付く科目の分類変更も禁止。
- 保管は一覧から外して記帳を止める操作。復帰可能。売却・除却仕訳は自動生成しない。
- 対応外: 会計開始日前に使用開始した資産・過年度償却済み資産の移行、家事按分、無形資産、旧償却法、少額資産/一括償却等の特例、短期事業年度、任意の過去償却額の調整。画面に対象範囲を表示。適用する税務上の方法・耐用年数は利用者が確認する。

- `/reports` に入金予定、支払予定、収益、費用、損益、資金繰り、部門別、分類・振込先を用意。期間は24か月まで。表は100行、分類は50件ずつ。全7レポートにグラフ・一覧・CSV/PDF出力。PDFは表形式・1,000行まで。
- 入金予定は現在未入金の発行済み請求書を期日で集計。将来発行日、合算元、下書きは除外。振込見込みには源泉徴収差引後の金額を使用。過去時点の売掛残高表ではない。
- 支払予定は支払管理の未払いと経費精算の承認済み未精算を統合。経費精算は追加の精算予定日を指定可能。未指定分は支払一覧に含め、予測からは除外。
- 収益ランキングは発行済み請求書の税抜売上、商品別は明細額を集計。取引先名＋取引先コードで同名会社を区別。損益・費用は登録済み仕訳だけを税込経理で集計。支払/入金仕訳を費用/売上として加算しない。取消仕訳は実際の記帳日に符号を反転して含める。
- 資金繰りは今日から6か月（期間フィルターとは独立）。開始残高は標準の現金・普通預金と銀行明細取込に指定された資産科目の帳簿残高。過去の開始残高仕訳が必要。未来の未登録取引・定期請求の未生成分は予測しない。期限超過の入金/支払、精算予定日未指定は金額を別表示し、予測から除外。
- 部門・事業所は1取引に各1つ、60文字まで。候補を再利用できる自由入力。「未分類」で抽出可能。同じ請求書・支払い・経費精算・資産の仕訳と取消仕訳は元データの分類を共有。手入力/CSV仕訳は伝票単位。変更は過去のレポートにも反映。部門等を絞ると全社預金の配賦は行わず、資金繰りの残高欄を非表示にして差引のみ表示。
- 振込先は支払い・精算ごとに銀行/支店コード・預金種目・7桁の口座番号・半角名義を追加保存。対象全件の予定日と振込先がある場合のみ一括振込準備CSVを出力。未払い状態を再取得し、コードの先頭ゼロをファイル中に保持。**共通CSVであり銀行別の直接取込形式・全銀固定長ファイルではない**。銀行に合わせた変換・利用者による内容確認が必要。送金や支払済みへの変更は実行しない。
- `ReportAnnotation` は追加テーブルのみ。元の請求書・取引先・仕訳・金額を更新しない。所有者を認証から固定し、変更時は実在する元取引の所有権を再検証。所有者ロックと整数版番号で並行操作と古い画面の上書きを拒否。
- レポートはRepeatableReadで読み取りを統一。元データ各10,000件、期間内仕訳5,000件まで（超過は切捨てずエラー）。APIは認証必須・private/no-store・nosniff、CSV数式インジェクション対策、PDF同時生成数制限、日本語フォントの本番同梱設定。
- ローカルDBを `work/accounting-dev/before-phase6-20261003.dump` に保存後、追加マイグレーション `20261003090000_management_reports` を適用。本番反映は未実施。
- 検証中にローカルログイン後の絶対URLリダイレクトがlocalhost/127.0.0.1を切り替える事象を確認。固定パスへの相対303リダイレクトに変更してCookieのホストを維持。

## フェーズ7: 事業所メンバーの権限管理・操作ログ（2026-10-03・第1段階）

- 「事業所」は所有者ユーザーのIDで識別する。既存の所有列（`userId` / `createdById`）と複合外部キーは変更せず、メンバーは所有者の事業所へ参加して同じデータを共有する。1ユーザーは1事業所のメンバーのみ。所有者は暗黙の管理者。
- 権限は4段階: 閲覧のみ < 入力可 < 承認可 < 管理者。サーバー側は `requireWorkspace(最低権限)` / `requireWorkspacePage(最低権限)` で統一。
  - 閲覧のみ: 帳簿・請求書・レポートの閲覧とCSV/PDF出力。
  - 入力可: 請求書・取引先・テンプレート・仕訳・支払・入金記録・明細取込・償却の記帳・部門分類。
  - 承認可: 上記に加え、仕訳の取消、入金消込の取消、償却記帳の取消、振込準備CSVの出力。
  - 管理者: 上記に加え、勘定科目、会計初期設定、固定資産の登録・保管、銀行口座・自動登録ルール、自社情報・設定、メンバー管理、操作ログ閲覧。
- 「設定 → メンバー・権限」（`/settings/members`）で、登録済みメールアドレスのユーザーを追加・権限変更・停止/再開。**請求書・取引先・会計データ・経費精算の精算先をすでに持つアカウントは追加できない**（データが見えなくなるのを防ぐため。データ移行機能は未実装）。停止したメンバーは旧事業所へ戻らず、自分の空の事業所になる。追加・権限変更は本人へアプリ内通知。
- 操作ログ（`AuditLog`）: 設定 → 操作ログ（`/settings/audit`、管理者のみ）。仕訳登録・取消、勘定科目、請求書の作成・更新・複製、取引先、自社情報、入金記録・消込、支払、定期請求・合算、明細取込・承認・ルール変更、固定資産・償却、レポート分類、メンバー変更、経費申請の処理（申請・承認・差戻し・精算・取消）、CSV/PDF出力を記録。操作者・日時・対象・要約。元の変更と同一トランザクションで保存し、ロールバック時はログも残らない。DBトリガーで更新・削除不可。金額の一覧やファイル内容は要約に含めない。
- 承認履歴: 経費精算は従来どおり申請ごとの履歴（`ClaimEvent`）を保持し、処理は操作ログにも記録。
- UI: 権限がない画面は一覧画面へ戻し、閲覧のみのユーザーには「請求書を作成」「取引先を追加」「取引を入力」「資産を登録」を表示しない。サイドバーに権限を表示。
- マイグレーション `20261003100000_workspace_permissions` は追加のみ（`WorkspaceMember` `AuditLog`、権限値と自己参加のCHECK、ログの更新・削除禁止トリガー）。適用前にローカルDBを `work/accounting-dev/before-phase7-20261003.dump` に保存。本番反映は未実施。
- 経費精算（`ClaimWorkspace`/`ClaimMember`）は独自の「申請のみ／申請・承認」権限のまま。事業所の権限とは**統合していない**（別の精算先へ申請する使い方を保つため）。統合するかは別途相談。
